# Proposal contract

Produce:

1. Level decision and audience.
2. Current-state summary with evidence labels.
3. Proposed documentation tree.
4. Disposition table: current path, action, destination, rationale, evidence.
5. Content outline for every added or substantially revised file.
6. Diagram specifications and the questions they answer.
7. Install-path matrix: existing, proposed, unsupported, and verification method.
8. Implementation sequence with dependencies.
9. Acceptance criteria and safe validation commands.
10. Explicit exclusions, risks, unknowns, and owner questions.

Prefer a small root README that routes depth into task-based guides, factual reference, and architecture explanation. Avoid mirroring the same prose into README, agent instructions, and technical docs.
